# Правила разметки сущностей

Используются в золотом наборе `eval/entities_gold.jsonl` и в промпте извлечения (`nlp/entities.py`).

## Типы

| Тип | Что размечаем | Примеры |
|---|---|---|
| `method` | Методы, алгоритмы, архитектуры, названные модели и технологии | speculative decoding, EAGLE-2, kNN, Transformer, машинное обучение, Интернет вещей |
| `dataset` | Названные датасеты и бенчмарки | MT-Bench, GSM8K, WMT 2014 De-En, CNN/DailyMail |
| `metric` | Меры качества и скорости, по которым сравнивают | speedup, acceptance rate, throughput, latency, BLEU, Logg-Loss |
| `task` | Задачи и приложения | machine translation, summarization, диагностика заболеваний |

## Правила

1. Название берётся так, как написано в тексте (в любой словоформе — сравнение идёт по основам слов).
2. Одна сущность — одна запись. Полное имя и сокращение — синонимы через «|»: `Approximate Speculative Decoding|ASD`.
3. Не размечаются: зонтичный термин «искусственный интеллект» / AI; общие слова без названия (model, method, dataset); числа и результаты («30%», «5x»); оборудование (RTX 4090).
4. Только то, что есть в тексте: знание из других источников не добавляется.

## Известные спорные места

- Граница `task` и области применения: «LLM inference», «autoregressive generation» — задача или контекст? В черновом наборе такие фразы **не** размечены как задачи, и модель на них теряет точность.
- Названные модели (LLaMA-2, Qwen3-14B) размечены как `method`; модель часто их пропускает или относит к `dataset`.
- Статус набора — `draft`: разметку делал один человек, без второго разметчика и согласия между ними.
