# Ассистент исследователя

ИИ-агент, который по заданной теме собирает научные статьи, хранит и размечает их, ищет по ним и отвечает на вопросы точными цитатами со ссылкой на статью, раздел и страницу.

Проект по курсу «Агентный ИИ: теория и инженерия» (MMCS, осень 2026). План и архитектура — в [PLAN.md](PLAN.md).

## Запуск

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync
cp .env.example .env    # затем вписать адрес сервиса, ключ и модель
uv run research-assistant check
uv run pytest
```

`check` делает один запрос к модели и показывает, умеет ли она вызывать инструменты и возвращает ли счётчики токенов. Без этого агент работать не будет.

## Модель

Подойдёт любой сторонний AI-сервис с OpenAI-совместимым API и вызовом инструментов. Готовые профили: `lmstudio` и `ollama` (локально), `inception` (Mercury 3), `openai`, `anthropic`, `openrouter`, `deepseek`, `gemini` и `custom` (любой свой адрес). Провайдер выбирается одной строкой в `.env`, у каждого свой ключ, так что можно держать несколько и переключаться:

```
LLM_PROVIDER=inception          # или lmstudio, openrouter, anthropic…
INCEPTION_API_KEY=<ключ>        # ключи — под стандартными именами: OPENROUTER_API_KEY, ANTHROPIC_API_KEY…
LLM_OPENROUTER_MODEL=<vendor/model>   # модель профиля, если у него нет проверенной модели по умолчанию
```

```bash
uv run research-assistant providers                        # профили: адрес, модель, есть ли ключ
uv run research-assistant check                            # выбранный профиль вызывает инструменты?
uv run research-assistant --provider lmstudio ask "…"      # разово другой провайдер, без правки .env
```

Все переменные с пояснениями — в `.env.example`. Эмбеддинги bge-m3 для облачных провайдеров по умолчанию берутся из LM Studio: индекс библиотеки посчитан ими. Старая схема без `LLM_PROVIDER` (`OPENAI_BASE_URL`, `OPENAI_API_KEY`, `MODEL`) тоже работает.

На Mercury 3 агент отвечает за 10–30 с и заметно точнее Qwen3.5-4B. В облако уходят вопрос и найденные фрагменты статей. Если LM Studio выключен, поиск сам переходит на BM25 (по словам), агент получает об этом подсказку и ищет английскими словами в английских статьях. Это работает, но по-русски в английских статьях с эмбеддингами ищется лучше.

## Сбор статей

```bash
# английские статьи: OpenAlex + arXiv, по 40 результатов из каждого источника, с 2023 года
uv run research-assistant ingest "speculative decoding" --limit 40 --year-from 2023

# русские статьи: только OpenAlex с фильтром по языку
uv run research-assistant ingest "машинное обучение в медицине" --language ru --limit 30

# что лежит в библиотеке
uv run research-assistant library
uv run research-assistant library --topic "speculative decoding"
```

Широкую тему одним запросом не собрать: источник находит только статьи со словами запроса, а русские слова OpenAlex не склоняет. Поэтому тему собирают набором формулировок и отсеивают постороннее:

```bash
# несколько формулировок в одну тему; --limit действует на каждую (OpenAlex — до 2000, постранично)
uv run research-assistant ingest "ИИ в общепите" --query "искусственный интеллект ресторан" \
    --query "artificial intelligence restaurant" --limit 100

# формулировки из файла, фильтр по словам темы и статьи без открытого доступа (в библиотеку попадёт аннотация)
uv run research-assistant ingest "ИИ в общепите" --queries-file queries/ai_foodservice.txt --limit 60 \
    --require "ресторан|общественное питание|restaurant|food service" \
    --require "искусственный интеллект|нейросеть|machine learning|AI" --include-closed

# работы российских авторов находятся и по английским запросам («public catering»)
uv run research-assistant ingest "ИИ в общепите" --query "public catering" --country RU --sources openalex --limit 200

# статья, которую поиск не нашёл: по DOI, идентификатору arXiv или адресу страницы (например, CyberLeninka)
uv run research-assistant add 10.1234/abc 2402.01528 https://cyberleninka.ru/article/n/... --topic "ИИ в общепите"
```

`--require` — группа слов через `|`: хотя бы одно должно быть в названии или аннотации (сравниваются основы слов, фраза — слова подряд); флаг повторяется, тогда нужны слова из каждой группы. Без фильтра поиск OpenAlex подмешивает постороннее: он ищет и по полному тексту. Готовые наборы запросов по общепиту и скрипт сбора — в `queries/` (`bash queries/collect.sh ai|marketing|ru`).

Полные тексты качаются в несколько потоков (`--workers`, по умолчанию 6); один сайт всегда достаётся одному потоку, поэтому паузы из robots.txt соблюдаются. У OpenAlex без ключа бесплатный дневной лимит — около 100 поисков на IP, сброс в полночь UTC. Когда он исчерпан, `ingest` сообщает об этом и идёт дальше с тем, что уже найдено; ту же команду можно повторить позже, найденное не теряется. С бесплатным ключом (`OPENALEX_API_KEY` в `.env`) лимит больше. Издатели закрытых статей обычно отвечают роботам отказом (403): по таким статьям в библиотеке остаётся аннотация.

Статьи из разных источников склеиваются по DOI, идентификатору arXiv, идентификатору OpenAlex и нормализованному заголовку. Полные тексты сохраняются в `data/fulltext/`: PDF или HTML-страница статьи CyberLeninka. Если прямой ссылки на PDF нет или она не сработала, открывается страница статьи (адрес из источника или `https://doi.org/<DOI>`) и PDF берётся из метатега `citation_pdf_url` — так находятся тексты в журналах, для которых источник знает только страницу. Перед скачиванием проверяется robots.txt сайта, паузы между запросами берутся из его Crawl-delay (у arxiv.org это 15 секунд, поэтому сбор 30 статей занимает минут десять). Ответы API кэшируются в `data/cache/`; флаг `--refresh` их обходит, `--retry-failed` повторяет неудачные скачивания, `--no-fulltext` пропускает скачивание.

## Разбор полных текстов

`ingest` сразу разбирает скачанные статьи (флаг `--no-parse` это отключает). Отдельно:

```bash
uv run research-assistant parse                  # разобрать всё, что ещё не разобрано текущей версией
uv run research-assistant parse --force --paper 10
uv run research-assistant show 10                # разделы и фрагменты со страницами
uv run research-assistant show 10 --sentences    # предложения с ID: на них будут ссылаться цитаты
```

Статья делится на разделы с типом (`introduction`, `method`, `results`, `appendix`…), разделы — на фрагменты до 220 слов, фрагменты — на предложения. У каждого предложения есть позиция в тексте фрагмента и номер страницы PDF. Колонтитулы, сноски, формулы, шапка статьи и список литературы отбрасываются. Если полного текста нет, в поиск попадает аннотация из метаданных.

Таблицы с числами разбираются отдельно (парсер версии 2): строки PDF, стоящие на одной высоте, — ячейки одной строки таблицы. Таблица становится фрагментом вида `table`, а её строка — «предложением» с ячейками через ` | ` (`Density | 0.60 | 0.79 | 0.73`): строку можно найти поиском и процитировать по ID. Раньше таблица склеивалась в один абзац без границ строк или отбрасывалась как формула. Таблицы без чисел и формулы по-прежнему разбираются как обычный текст. Если PDF статьи нет на диске (базу перенесли без `data/fulltext/`), прежний полный разбор не трогается — в выводе `parse` такая статья помечена `kept`.

## Поиск

```bash
uv run research-assistant search "how does tree-based verification work" --k 5
uv run research-assistant search "ограничения метода" --section limitations --topic "speculative decoding"
uv run research-assistant search "draft model latency" --mode bm25     # bm25 | dense | hybrid
```

BM25 работает сразу: полнотекстовый индекс SQLite FTS5 строится вместе с разбором, слова приводятся к основам (английский и русский). Для плотного поиска нужна многоязычная модель эмбеддингов — по замерам лучшая из опробованных `bge-m3` (в LM Studio: `lms get https://huggingface.co/ggml-org/bge-m3-Q8_0-GGUF`, затем `EMBED_MODEL=text-embedding-bge-m3` в `.env`). Векторы считаются один раз и потом досчитываются для новых статей:

```bash
uv run research-assistant index
```

По умолчанию поиск гибридный: списки BM25 и плотного поиска сливаются по местам (Reciprocal Rank Fusion). Без эмбеддингов он сам переключается на BM25.

Два необязательных шага на чат-модели из `.env`:

```bash
uv run research-assistant search "ограничения черновой модели" --translate   # + BM25 по английскому переводу запроса
uv run research-assistant search "draft model latency" --rerank              # переупорядочить 20 лучших кандидатов
```

`--translate` помогает искать по-русски в английских статьях: BM25 ищет и по исходному запросу, и по переводу. `--rerank` — listwise-реранкер (подход RankGPT): модель за один вызов упорядочивает 20 кандидатов. В оценке поиска это режимы `hybrid+translate`, `hybrid+rerank` и их сочетание.

## Оценка поиска

```bash
uv run research-assistant eval-retrieval                 # Recall@5/10, MRR@10, nDCG@10 по режимам
uv run research-assistant eval-retrieval --modes bm25
```

Результаты экспериментов — в [docs/experiments.md](docs/experiments.md). Вопросы лежат в `eval/retrieval_gold.jsonl`: ответ задан названием статьи и дословной цитатой, поэтому набор не ломается при переразборе. Метрики считаются отдельно для групп «язык вопроса→язык статьи» (en→en, ru→en, ru→ru), подробности по каждому вопросу сохраняются в `runs/`.

## Агент

```bash
uv run research-assistant ask "Почему спекулятивное декодирование хуже работает для малоресурсных языков?"
uv run research-assistant chat            # диалог в терминале; пустая строка или /exit — выход
uv run research-assistant chat --offline  # без поиска новых статей в OpenAlex/arXiv
```

Сначала код ищет по самому вопросу и отдаёт результаты агенту, дальше агент сам ищет по библиотеке (в том числе на втором языке), при необходимости читает соседние фрагменты и отвечает утверждениями с дословными цитатами: статья, раздел, страница, ID предложения. Цитаты подставляет код по ID, поэтому они всегда дословные; ответ принимается, только если агент действительно видел процитированные предложения в выдаче. По просьбе пользователя агент может найти новые статьи (`search_external`) и добавить их в библиотеку (`add_papers`). Каждый прогон пишется в `runs/*.jsonl`: шаги, вызовы инструментов, ошибки, токены.

Локальная модель в LM Studio должна быть загружена с достаточным контекстом:

```bash
lms load qwen3.5-4b --context-length 16384 --gpu max -y
```

В `.env`: `MODEL=qwen3.5-4b`, `REASONING_EFFORT=none` (иначе Qwen3.5 тратит сотни токенов на «размышления» на каждом шаге).

Вопросы про авторов и конкретные статьи («какие статьи у Tri Dao») агент решает инструментом `find_papers` (поиск по автору, названию и аннотации), а цитаты потом ищет внутри найденных статей (`search_library` с `paper_ids`). Для сравнения статей у агента есть инструмент `compare_papers`: по каждой статье он показывает её разметку (датасеты, метрики, методы) и лучшие фрагменты по заданному аспекту, например «speedup on MT-Bench».

Бюджет агента зависит от того, где работает модель. У локальной модели (LM Studio, Ollama) — 6 поисков и наблюдения до 6000 символов: маленькая модель иначе не останавливается. У облачной — 12 поисков, наблюдения до 14000 символов и две подсказки в системном промпте: отвечать на языке вопроса и отвечать на каждую часть вопроса (до 10 утверждений), прямо называя непокрытые части. Подсказки не входят в `prompt_hash`, датасет дообучения с ними совместим. Переменные: `MAX_RESEARCH_CALLS`, `MAX_OBSERVATION_CHARS`, `ANSWER_HINTS`.

Если поиск остался без эмбеддингов (сервер выключен, в нём нет модели) или индекс покрывает не всю библиотеку, запрос переводится чат-моделью и BM25 ищет на обоих языках: русский вопрос находит английскую статью и наоборот.

### Чтение статьи целиком и проверка «чего нет»

Ответ агента строится по лучшим фрагментам на запрос. Этого хватает для фактов, которые статья сама формулирует, и не хватает для утверждений о новизне: вывод «в библиотеке этого нет» означает лишь «по моей формулировке ничего не нашлось», ход рассуждения рвётся на фрагменты, расхождение текста с таблицей не видно. Для этого есть две команды.

```bash
# прочитать статью целиком: что в ней есть (с цитатами), чего нет, расхождения внутри статьи
uv run research-assistant read 136
uv run research-assistant read 136 --aspect "рестораны и кафе как тип помещения" --aspect "учёт выручки"
uv run research-assistant read 98 --question "Как авторы учитывают расположение ресторана внутри города?"

# задать один вопрос каждой статье темы: рассмотрен ли в ней аспект
uv run research-assistant coverage "расстановка мебели в помещении непрямоугольной формы" --topic resto-gen
```

`read` выдаёт модели весь текст статьи по порядку, с ID у каждого предложения и строки таблицы. Короткая статья читается за один вызов, длинная — окнами с заметками, по которым пишется отчёт (`READ_WINDOW_CHARS`). В отчёте: находки по рубрикам с цитатами по ID, список «чего в статье нет» и расхождения между частями статьи. Утверждение без верного ID в отчёт не попадает; по статье, у которой в библиотеке только аннотация, выводы об отсутствии не делаются.

`coverage` сначала просит модель переформулировать аспект (синонимы, русский и английский варианты), упорядочивает статьи темы по близости к формулировкам и по каждой из первых `--limit` (60) выносит вердикт по её лучшим фрагментам: рассматривает, частично или в другой постановке, не рассматривает. Отчёт перечисляет границы проверки: сколько статей проверено, сколько нет, у скольких только аннотация. Это проверка по фрагментам; ближайшие аналоги из отчёта стоит прочитать целиком через `read`. Журналы обеих команд — `runs/read-*.jsonl`, `runs/coverage-*.jsonl`.

### Оценка агента

```bash
uv run research-assistant eval-agent                     # итеративный агент на 30 золотых вопросах
uv run research-assistant eval-agent --variant single    # один поиск по вопросу и сразу ответ (эксперимент E3)
uv run research-assistant eval-agent --variant quotes    # цитаты текстом от модели, а не по ID (эксперимент E2)
uv run research-assistant eval-agent --runs 3            # повторы: pass@1 с интервалом Вильсона и pass^3
```

Ответ успешен, если агент сдал `final_answer` и хотя бы одна его цитата лежит во фрагменте с золотым ответом. В режиме `quotes` дополнительно считается доля цитат, которые дословно есть в библиотеке.

## Разметка

```bash
uv run research-assistant annotate                       # сущности и ключевые слова для неразмеченных статей
uv run research-assistant entities --type dataset --topic "speculative decoding"
uv run research-assistant search "speedup results" --entity "MT-Bench"
uv run research-assistant eval-entities                  # P/R/F1 на золотом наборе eval/entities_gold.jsonl
```

Модель из `.env` находит в аннотации, заключении и начале экспериментов методы, датасеты, метрики и задачи; остаются только названия, которые действительно есть в тексте. Сущности привязываются ко всем фрагментам статьи, где упоминаются, поэтому поиск можно ограничить фрагментами про конкретный датасет или метод. Ключевые слова считает YAKE. Агент использует разметку сам: на вопрос «какие датасеты используют» он вызывает `list_entities`, а затем ищет цитаты с фильтром по сущности. Правила разметки — в [docs/annotation_guidelines.md](docs/annotation_guidelines.md). `ingest --annotate` размечает новые статьи сразу после сбора.

## Веб-интерфейс

```bash
uv run research-assistant ui              # откроет http://localhost:8501
uv run research-assistant ui --no-browser --port 8600
```

Три раздела в боковой панели:

- **💬 Вопрос по статьям** — чат с ассистентом. Пока он работает, видно, что он делает («Ищу в библиотеке: …», «Ищу статьи: автор …»). Под ответом — блок «Откуда это известно»: дословные цитаты со статьёй, разделом и страницей, кнопка «Открыть PDF на с. N» и абзац целиком с выделенной цитатой. Для нового пользователя — приветствие и примеры вопросов. Если модель не запущена, страница так и говорит, что сделать.
- **📄 Статьи** — поиск статей по автору («Tri Dao», «Барсуков») и по словам из названия и аннотации в любой словоформе; нужны все слова запроса. Ниже идут статьи, похожие по смыслу, в том числе на другом языке. Фильтры по теме, языку и годам; у статьи открывается карточка с аннотацией, разметкой и текстом по разделам.
  Вкладка «🌐 Новые статьи в интернете» ищет по тем же полям в OpenAlex и arXiv. По автору поиск идёт именно по авторству: в OpenAlex через профили авторов, в arXiv через поле `au:`, затем имя сверяется со списком авторов. Поэтому «Geoffrey Hinton» даёт его работы, а не статьи о нём. Нужные статьи отмечаются галочками и добавляются в выбранную или новую тему.
- **🔍 Поиск цитат** — абзацы из полных текстов по запросу, с подсветкой слов запроса и уточнениями (раздел, язык, сущность, способ поиска, перевод запроса).

Если в настройках разрешён поиск в интернете, ассистент в чате тоже ищет новые статьи, в том числе по автору. Найденное показывается под ответом с галочками «Добавить в библиотеку». Сам ассистент добавляет статьи, только если вы прямо попросили («добавь», «скачай», «сохрани»). Без такой просьбы инструмента добавления у модели нет: Qwen 4B на «найди статьи» сама скачивала их в библиотеку.

**История чатов** сохраняется автоматически: каждый чат — файл в `data/chats/`, список в боковой панели, чат можно открыть и продолжить (ассистент помнит последние 3 вопроса) или удалить. Подробный журнал шагов — `runs/ui-<id чата>.jsonl`.

Логика страниц лежит в `ui/views.py` отдельно от Streamlit и покрыта тестами; `ui/app.py` только раскладывает её по виджетам.

## Библиотека в других агентах (MCP)

```bash
uv run research-assistant mcp                 # только чтение: поиск, чтение фрагментов, cite
uv run research-assistant mcp --allow-model   # + ask_agent, read_paper, check_coverage (тратят ключ)
uv run research-assistant mcp --allow-write   # + поиск в OpenAlex/arXiv и добавление статей
```

MCP-сервер по stdio даёт Claude Code, Hermes Agent, Codex, Cursor и другим агентам те же инструменты, что у собственного агента, и инструмент `cite`: внешний агент передаёт ID предложений, а дословную цитату с разделом и страницей подставляет код. Claude Code подхватывает сервер из `.mcp.json` в корне проекта. Навык `skills/research-library/SKILL.md` объясняет агенту порядок работы и правила цитирования. Подключение к каждому клиенту — в [docs/mcp.md](docs/mcp.md).

## Дообучение локальной модели

Агент на Qwen3.5-4B дообучается на траекториях облачного учителя Mercury 3 (LoRA SFT). Подробно — в [docs/finetune.md](docs/finetune.md):

```bash
uv run research-assistant ft-split                     # статьи: train / val / test (тест — статьи золотого набора)
uv run research-assistant ft-questions --split test    # вопросы учителем; затем --split val, --split train
uv run research-assistant ft-collect --split train     # траектории учителя (нужен bge-m3 в LM Studio)
uv run research-assistant ft-export                    # примеры SFT: шаблон чата из GGUF, маска потерь
uv run python scripts/make_train_bundle.py             # zip для обучения на ПК с RTX 5070 + инструкция
```

Обучение идёт на другом ПК по `README_RTX5070.md` внутри архива. Готовый GGUF импортируется в LM Studio и оценивается тем же `eval-agent`. Модель и датасет не публикуются: так требуют условия Inception.
